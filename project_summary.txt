Follower Competition Channel - Project Summary (as of Feb 1, 2026)

Origin story
During my first months in Kongsvinger I saw Instagram videos where a channel made all their followers compete in a simple race. I had some Python background and decided to build a more ambitious version: a full daily tournament system with multiple games and real follower data. That idea became the Follower Competition Channel, which now runs mostly hands-off.

Today the channel is a 24/7 pipeline that:
- collects followers, updates profile pictures, and builds a clean roster
- runs a suite of game simulations in a vertical 9:16 format
- exports videos automatically
- tracks every result and updates leaderboards
- publishes to social platforms and updates a website and Discord with stats

Current scale (approx): ~150,000 followers, ~10,000,000 total views, ~2,500 new followers/day. Day numbers are tracked in config.py (Day 73 as of Feb 1, 2026), and every game run is tagged with a day number and timestamp so results stay consistent.

How the system works (big picture)
1) Input: follower lists from safe exports, Graph API, scrapers, or TikTok imports.
2) Processing: followers are normalized, avatars are cached, and a per-day roster is prepared.
3) Simulation: a list of game modes runs one by one (config.ALL_GAME_MODES).
4) Output: each game exports an MP4 and writes results into game_history + player_statistics.
5) Publishing: stats are partitioned for the website, pushed to GitHub, and videos are uploaded.
6) Community: the Instagram webhook and Discord bot serve results and rankings on demand.

Follower ingestion and roster management
- Primary source is safe imports (Instagram data export or CSV). There is also support for Graph API and optional scrapers (Instaloader / Apify / Selenium), plus a TikTok import file.
- Followers live in JSON files under Followers/ with fields like username + profile_pic_url.
- append_new_followers.py, merge_followers.py, and incremental_profile_pic_update.py keep the list up to date without losing existing data.
- shared/api.py caches follower data in memory so multiple games can reuse the same roster during a daily run.

Profile picture pipeline
- avatar_cache/ stores one JPG per username for fast loading.
- download_all_profile_pics.py builds the cache; check_cache_status.py shows coverage.
- Missing or failed images fall back to colored circles so the games never block on network calls.

Game engine and simulation layer
- All games are Pygame-based and render in 540x960 (9:16) for Reels/TikTok.
- Shared templates (shared/game_template.py, renderer_template.py, arena_template.py, entity_template.py) enforce a consistent UI layout, scoring, and video export flow.
- Core subsystems include physics, collision, AI movement, particle effects, sound, and a scoreboard overlay.
- Games are modular: each game folder (battle_royale, fighter_arena, maze_rush, mini_golf, flappy_followers, super_follower_bros, etc.) contains its own arena, entity logic, and renderer.
- Some games are non-scoring or community-gated (for example, mingle and lava_platform are non-scoring; some games are Discord-only or club-only).

Scoring, stats, and history
- Scoring is placement-based (100 points for 1st, descending). Some game types are marked non-scoring.
- player_statistics.json tracks per-player lifetime stats: points, games played, best placement, wins, streaks, kills, damage, and more.
- game_history.json stores full results for every game session (game_id, day_number, timestamp, placements).
- Monthly leaderboards and Hall of Fame data are generated from history.

Scaling and data architecture
- Local monolithic files can be huge, so the project exports partitioned API files under website/public/api/:
  - index.json (master index)
  - days/{day}.json (day summaries)
  - games/{game_id}.json (full results per game)
  - types/{game_type}.json (all games of a type)
  - players/{letter}.json and player_history/{letter}.json (partitioned player data)
- This keeps the website fast and avoids Git LFS limits. Auto-push only commits the partitioned API folder.

Video production
- Frames are captured and streamed to disk in shared/recorder.py (OpenCV), avoiding high memory usage.
- Optional upscaling creates higher-quality exports.
- Audio is mixed from logged events, and a countdown overlay can be composited.
- MP4s are stored by day in the Videos/ and Uploaded videos/ folders.

Automation and publishing
- daily_automation_loop.py is the factory script:
  - push stats to GitHub
  - upload videos to Instagram and TikTok with randomized 2-3 hour delays
  - wait until 6 AM, increment day number, fetch new followers, run all games, repeat
- Upload paths include a safe Selenium-based uploader (safe_instagram_uploader.py) and a persistent session uploader for speed.
- post_run_publish.py can publish immediately after a manual run.

Website and community layer
- React/Vite/Tailwind site under website/ with pages for Daily Results, Monthly Rankings, Player Profiles, Hall of Fame, Media Kit, Privacy, and Member Club.
- DataLoader fetches partitioned API files on demand and caches aggressively for fast browsing.
- GitHub Actions deploy the site; a custom domain is supported via website/public/CNAME.

Instagram webhook and Discord bot
- instagram_webhook.py (Flask + ngrok) listens to comment triggers (for example, "result") and replies with the user's placement, pulling from the same API data.
- Reply queues and rate limits prevent IG blocks, and some games can be Discord-only or member-only.
- discord_bot/ provides slash commands and lets members link Discord and Instagram names.

Operational guardrails and recovery
- TEST_MODE can disable stat writes; TEST_MINIMAL_PLAYERS enables quick dev runs.
- Automation state is stored in automation_state.json and logs in logs/.
- Recovery scripts can rebuild API indexes or recover history if something breaks.

Tech stack summary
- Python (core engine), Pygame (rendering), NumPy/Numba (performance), OpenCV + MoviePy/FFmpeg (video), Pillow (images)
- Selenium + instagrapi (uploads), Flask (webhook), Discord.py (bot), requests (API calls)
- React + Vite + Tailwind (website), GitHub Actions + Pages (deployment), ngrok (webhook tunneling)

In short: this is a full content production pipeline that turns a live follower list into daily game videos, persistent stats, and an interactive community experience across Instagram, Discord, and a dedicated website. It started as a simple race idea and evolved into a multi-game tournament system with real automation, data engineering, and production tooling behind it.
